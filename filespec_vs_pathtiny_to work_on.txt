

File::Spec is a core Perl module that helps you construct and manipulate file and directory paths without hardcoding the path separator.

It's particularly useful when writing scripts that need to work on Linux, macOS, and Windows.

Let's look at some basic examples, using your Thompson music files as the context.
1. Loading the module


use File::Spec;

You don't normally need to install it separately because File::Spec is included with Perl.
2. catfile() — Construct a file path

This is probably the most useful method for your script.

use File::Spec;

my $dir  = '/home/music/Thompson';
my $file = '1 Thompson title.aac';

my $path = File::Spec->catfile($dir, $file);

print "$path\n";

/home/music/Thompson/1 Thompson title.aac

##-----------------------------------------------------##
## Why use catfile() instead of concatenating strings? ##
##-----------------------------------------------------##

my $path = "$dir/$file";

But that assumes / is the path separator you want. catfile() constructs the path using the conventions of the current operating system.

For your renaming script, this is exactly what we need:

my $source = File::Spec->catfile($dir, $file);
my $target = File::Spec->catfile($dir, $newfile);

These construct the full source and destination paths.
3. catdir() — Construct a directory path

Use catdir() when constructing a directory path rather than a file path.

use File::Spec;

my $base = '/home';
my $user = 'music';
my $album = 'Thompson';

my $dir = File::Spec->catdir($base, $user, $album);

print "$dir\n";

/home/music/Thompson

You can supply as many directory components as you need:

my $dir = File::Spec->catdir(
    '/home',
    'music',
    'Croatian',
    'Thompson'
);

This is useful when building directory names dynamically.
4. splitpath() — Separate a path into components

Suppose you have a complete filename:

my $path = '/home/music/Thompson/1 Thompson title.aac';

my ($volume, $directories, $file) =
    File::Spec->splitpath($path);

print "Volume:      $volume\n";
print "Directories: $directories\n";
print "Filename:    $file\n";

Volume:
Directories: /home/music/Thompson/
Filename:    1 Thompson title.aac

The three return values are:

    Volume: The drive or volume component, if applicable. On Windows, this might be C:.
    Directories: The directory portion of the path.
    Filename: The final filename component.

This is useful when you have a complete path but need to extract its components.
5. splitdir() — Split a directory path

You can split a directory path into its individual components.

my $dir = '/home/music/Thompson';
my @parts = File::Spec->splitdir($dir);
print "$_\n" for @parts;

On Unix-like systems, the output is approximately:

home
music
Thompson

The initial empty component represents the leading /.

This method is useful when you need to examine the directory hierarchy.
6. curdir() and updir() — Current and parent directories

These methods return the operating system's conventional representations of the current and parent directories.

use File::Spec;

print "Current: ", File::Spec->curdir(), "\n";
print "Parent:  ", File::Spec->updir(), "\n";

Current: .
Parent:  ..

You can use them when constructing relative paths

my $parent = File::Spec->catdir(
    File::Spec->curdir(),
    File::Spec->updir()
);

print "$parent\n";

This constructs a path referring to the parent of the current directory.
7. rel2abs() — Convert a relative path to an absolute path

Suppose your script receives a directory name such as:

my $dir = 'music/Thompson';

You can convert it into an absolute paths

use File::Spec;

my $absolute = File::Spec->rel2abs($dir);
print "$absolute\n";

If your current directory is /home/user, the result would be:

/home/user/music/Thompson

You can also provide a base directory:

my $absolute = File::Spec->rel2abs(
    'Thompson',
    '/home/user/music'
);

Result:

/home/user/music/Thompson

This is helpful when your script accepts a relative directory argument but you want to work with a full path.
8. abs2rel() — Convert an absolute path to a relative path

The reverse operation is also available.

my $relative = File::Spec->abs2rel(
    '/home/user/music/Thompson/01 Thompson title.aac',
    '/home/user/music'
);

print "$relative\n";

Output:

Thompson/01 Thompson title.aac

This is handy when you want to display shorter paths to the user.
9. file_name_is_absolute() — Check whether a path is absolute

You can test whether a path is absolute:

use File::Spec;

my $path1 = '/home/music/Thompson';
my $path2 = 'music/Thompson';

print "Path 1 is absolute\n"
    if File::Spec->file_name_is_absolute($path1);

print "Path 2 is absolute\n"
    if File::Spec->file_name_is_absolute($path2);

On Linux, only the first path is absolute.

This can be useful when validating command-line arguments.
10. Putting it together with your music files

Here's a small example showing how File::Spec works with opendir() and readdir().

#!/usr/bin/env perl

use strict;
use warnings;
use File::Spec;

my $dir = shift // '.';

opendir(my $dh, $dir)
    or die "Cannot open directory '$dir': $!\n";

while (my $file = readdir($dh)) {

    next if $file eq File::Spec->curdir();
    next if $file eq File::Spec->updir();

    my $path = File::Spec->catfile($dir, $file);

    next unless -f $path;

    print "Filename: $file\n";
    print "Full path: $path\n";
    print "\n";
}

closedir($dh);


For each entry, the script constructs the full path and checks whether it is a regular file.
Notice the distinction:

    readdir() returns the filename, not the full path.
    catfile() combines the directory and filename into a path.
    -f checks whether that path refers to a regular file.

These three operations work together in many Perl file-processing scripts.
Quick reference

splitdir()	Split a directory into components	File::Spec->splitdir($dir)
curdir()	Get the current-directory notation	File::Spec->curdir()
updir()	Get the parent-directory notation	File::Spec->updir()

For more details, see the official Perl documentation for File::Spec documentation.
My recommendation

For everyday Perl scripting, start with these three:

    catfile() — Construct full paths to files.
    catdir() — Construct directory paths.
    rel2abs() — Convert a relative path to an absolute one.

Those three cover a large proportion of everyday directory and file manipulation tasks.

#### is this module different to path::tiny ####

Yes. File::Spec and Path::Tiny solve many of the same problems, but Path::Tiny provides a more modern, convenient interface for working with files and directories.

The main difference is that File::Spec concentrates on constructing and analysing path strings, whereas Path::Tiny provides path objects with methods for constructing paths, reading and writing files, copying files, and traversing directories.
1. The basic difference
File::Spec — part of core Perl

use File::Spec;

my $dir  = '/home/music/Thompson';
my $file = '1 Thompson title.aac';

my $path = File::Spec->catfile($dir, $file);

print "$path\n";

$path is a string containing the constructed path.

If you want to copy a file, you would typically combine File::Spec with another module, such as File::Copy:

use File::Spec;
use File::Copy qw(copy);

my $source = File::Spec->catfile($dir, $file);
my $target = File::Spec->catfile($dir, '01 Thompson title.aac');

copy($source, $target) or die "Copy failed: $!";

Path::Tiny — a CPAN module

use Path::Tiny;

my $dir  = path('/home/music/Thompson');
my $file = $dir->child('1 Thompson title.aac');

print "$file\n";

Here, $dir and $file are Path::Tiny objects rather than ordinary strings.

You can use methods on those objects to perform common filesystem operations.

For example, copying a file:

use Path::Tiny;

my $dir    = path('/home/music/Thompson');
my $source = $dir->child('1 Thompson title.aac');
my $target = $dir->child('01 Thompson title.aac');

$source->copy($target);

Notice how Path::Tiny combines path construction and file operations in one interface.
2. Comparing common operations

Here's how the two modules compare for everyday tasks.
Task	File::Spec	Path::Tiny
Build a file path	File::Spec->catfile($dir, $file)	$dir->child($file)
Get the current directory	Cwd::getcwd()	Path::Tiny->cwd
Check if a file exists	-e $path	$path->exists
Check if it's a regular file	-f $path	$path->is_file
Get the filename	File::Basename::basename($path)	$path->basename
Read a file	Use open or another module	$path->slurp
Write a file	Use open or another module	$path->spew($data)
List directory contents	opendir and readdir	$dir->children
Copy a file	Use File::Copy::copy	$source->copy($target)

The Path::Tiny methods are documented in the official module documentation.
3. Your music-file example using Path::Tiny

Let's rewrite your track-numbering script using Path::Tiny.

This version uses children instead of opendir and readdir, but performs the same task: it creates zero-padded copies while preserving the originals.
perl

#!/usr/bin/env perl

use strict;
use warnings;
use Path::Tiny;

my $dir = path(shift // '.');

die "Not a directory: $dir\n" unless $dir->is_dir;

for my $source ($dir->children(qr/\.aac\z/i)) {

    my $file = $source->basename;

    next unless $file =~ /^(\d+) (.+\.aac)$/i;

    my ($track, $rest) = ($1, $2);

    # Only process single-digit track numbers
    next if length($track) >= 2;

    my $newfile = sprintf("%02d %s", $track, $rest);
    my $target  = $dir->child($newfile);

    # Never overwrite an existing file
    if ($target->exists) {
        print "SKIP: $newfile already exists\n";
        next;
    }

    $source->copy($target);

    print "COPIED: $file -> $newfile\n";
}

print "Finished.\n";

Run it with:
bash

perl pad_tracks.pl "/path/to/your/music"

For example, the script creates 01 Thompson title.aac from 1 Thompson title.aac, leaving the original untouched.

One advantage here is that $source and $target are path objects. You can construct paths, inspect them, and copy files through their methods without separately calling File::Spec and File::Copy.
4. Is Path::Tiny a replacement for File::Spec?

For many everyday scripts, yes. But they aren't completely interchangeable.

There are three important distinctions:

    Availability: File::Spec is included with Perl, while Path::Tiny is an additional CPAN dependency that you may need to install. See Path::Tiny on MetaCPAN.
    Purpose: File::Spec focuses on path construction and parsing. Path::Tiny combines path manipulation with convenient filesystem operations.
    Return values: File::Spec generally returns strings. Path::Tiny returns objects that provide methods for working with the corresponding paths.

Also, Path::Tiny uses forward slashes internally, including on Windows, and is designed primarily for Unix-like and Windows filesystems. File::Spec provides more specialized path handling for different operating systems.

5. Which would I recommend?

For your Perl scripts, I'd choose based on the purpose:

    Small scripts that must run on a standard Perl installation: Use File::Spec, File::Copy, and Perl's built-in directory functions.
    Scripts that regularly manipulate files and directories: Use Path::Tiny. Its interface is generally simpler and more consistent.
    Scripts that read and write lots of text files: Path::Tiny is particularly convenient because of methods such as slurp, spew, and lines.

My recommendation: If you're learning Perl and expect to write more filesystem utilities, learn Path::Tiny. You can still use opendir and readdir when you want to, and you won't need to abandon Perl's built-in functions.

One final point: you can use Path::Tiny alongside File::Spec when necessary. You don't have to choose one exclusively.
