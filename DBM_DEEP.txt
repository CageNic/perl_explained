while (<DATA>) {
    push @records, {
        name => ...,

At each iteration:

Perl reads one line from DATA.
Creates one hash.
Pushes that hash reference into @records.
Moves to the next line.
But step 3 means the hash is kept in RAM.

So after 1,000,000 iterations:

line 1     → hash ─┐
line 2     → hash  │
line 3     → hash  │
...              │
line 1,000,000 → hash ┘
                  ↓
              @records
              (RAM)

The hashes don't get freed because @records still references them.

while (<DATA>) {
    my $record = {
        name => ...,
        age  => ...,
    };

    process($record);
}

So:

push @records, {...};

= read one at a time, but retain all of them

whereas:

process({...});

= read and process one at a time, then discard

One subtle point
This:

my $record = parse_line($line);

creates a Perl data structure, but that's fine. Once the loop moves on, the previous $record can become eligible for cleanup provided you haven't stored it somewhere else.

For example, this destroys the streaming advantage:

my @records;

while (my $line = <$fh>) {
    my $record = parse_line($line);

    push @records, $record;   # retains every record
}

Whereas this remains streaming:

while (my $line = <$fh>) {
    my $record = parse_line($line);

    do_something($record);
}

So the rule of thumb is:

Read → parse → use → discard → read next.

That's the pattern I'd use for your 1,000,000-line file + DBM::Deep names lookup if you don't genuinely need all million records simultaneously.
